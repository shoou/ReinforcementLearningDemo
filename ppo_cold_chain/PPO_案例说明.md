# PPO 案例：冷链仓库的一天如何用电

一家生鲜配送中心既要让冷库保持 **2–8°C**，又要在配送车出发前充满指定电量。仓库屋顶有光伏，另有一组储能电池。运营者每半小时决定三件事：**制冷功率、给车充多少电、电池充还是放**。晚高峰购电更贵；一天中最大的半小时取电量还会带来需量费用。今天省电而耗尽电池也不行，因为第二天仍需继续运营。


## 运行

以下命令在 `ppo_cold_chain/` 目录执行。

需要 Python 3.9+、`numpy`、`torch`、`matplotlib`：

```bash
python3 -m pip install numpy torch matplotlib
python3 ppo_cold_chain.py
```

默认用 8 个随机日组成一个采样批，训练 600 次 PPO 更新。训练期间用固定的 32 个验证日选择最佳模型，最后在固定的 100 个测试日上比较三种策略。可用 `--updates`、`--envs`、`--seed`、`--output` 调整实验。脚本输出：

- `ppo_output/ppo_model.pt`：训练所得策略参数。
- `ppo_output/metrics.json`：测试集成本分解、峰值和违约情况。
- `ppo_output/training_and_dispatch.png`：训练曲线、三种策略的成本，以及一个测试日的取电和库温轨迹。

## 业务问题怎样变成强化学习问题

一天有 48 步，每步半小时。车辆在当天中途到达、傍晚离开，所需电量为 24、28 或 32 kWh；具体时刻和需求每天变化。冷库有热惯性：关闭制冷会逐渐升温，开大制冷可以预冷，但会增加当下负荷。光伏与基础负荷也随天气和时间波动。

| PPO 元素 | 本案例中的定义 |
| --- | --- |
| 状态 `s_t` | 时间、电池电量、库温、车辆剩余充电量、车辆是否在场、离站倒计时、当天已出现的取电峰值、当前电价/光伏/基础负荷/室外温度，以及从当前时段起未来 2 小时的电价和光伏均值，共 13 维 |
| 动作 `a_t` | 电池 `{-3, 0, +3}` kWh × 车辆 `{0, 2, 4}` kWh × 制冷 `{关, 中, 强}`，共 27 个组合 |
| 随机性 | 每天生成不同的天气、光伏、负荷、电价扰动和车辆任务 |
| 单步奖励 | `r_t = -(购电费 + 新增需量费 + 电池磨损代理费) / 10` |
| 回合目标 | 最小化全天累计成本，同时满足温度、充电、储能和日终电量约束 |

其中，新增需量费按 `2 × max(0, 本步取电量 − 当日历史峰值)` 计算。把每步新增费用累加，正好得到与全天最大取电量对应的代理费用。这让策略不能只看眼前电价：在高负荷时段多充一点车，可能抬高整天的峰值成本。

### 硬约束与长短期权衡

环境在每步生成**动作掩码**，去掉会让电池越界、库温越过 2–8°C、车辆出发前无法充足电，或日终无法恢复至初始电池电量的动作。PPO 和两个对照策略使用同一套约束。训练中的探索因此仍满足这些模拟约束。

可讨论的时序权衡包括：中午光伏富余时给车充电，还是先给电池充电；提前预冷能否避免晚高峰的制冷负荷；为了压低单日峰值，是否值得在低价时充电、在高价时放电；车辆离站期限逼近时，如何接受不可避免的高价用电。

## PPO 在这里做了什么

策略网络输入状态，输出 27 个动作的 logits；无效动作被掩码后再按概率采样。价值网络估计 `V(s_t)`。每批采样数据只用于接下来的几轮更新，然后丢弃，符合 **on-policy** 训练方式。

使用 `γ = 1.0`、`λ = 0.97` 计算 GAE 优势。因为业务目标是一天的总费用，`γ = 1.0` 使当天晚些时候的费用与早些时候具有同等权重：

`δ_t = r_t + γV(s_{t+1}) − V(s_t)`，`A_t = δ_t + γλA_{t+1}`。

在回合边界，下一状态价值和下一步优势都置零。保存采样时旧策略给动作的对数概率，更新时计算 `ρ_t = π_new(a_t|s_t) / π_old(a_t|s_t)`。PPO 的策略目标为

`E[min(ρ_t A_t, clip(ρ_t, 0.8, 1.2) A_t)]`。

代码每批做 4 轮小批量更新，加入价值损失和熵奖励，并裁剪梯度。学习率从 `3e-4` 逐步降至 `3e-5`，熵系数从 `0.01` 降至 `0.001`，使训练前期保留更多探索、后期减弱探索。每 20 次更新评估一次固定验证日，保存验证成本最低的检查点，避免把最后一次更新的偶然波动当成最终策略。**裁剪比率**限制策略目标对过大概率比变化的优化激励，但不保证实际概率比始终落在 `[0.8, 1.2]`；动作掩码在采样和更新时保持一致，否则新旧概率比会失真。

## 实验结果与解释

现有 `ppo_output/metrics.json` 记录了随机种子 `42`、600 次更新的结果；该次运行的训练、验证和测试日种子没有重叠，三种策略使用相同的 100 个测试日：

| 策略 | 平均模拟日成本 | 平均日取电峰值 | 车辆违约 |
| --- | ---: | ---: | ---: |
| 固定班表：偏好中档制冷、尽量推迟充车、不主动使用电池 | 180.49 | 9.24 kWh/半小时 | 0 |
| 手写规则：按温度、电价、光伏调度 | 174.15 | 9.25 kWh/半小时 | 0 |
| PPO | **162.84** | **8.77 kWh/半小时** | 0 |

当前代码按 32 个验证日的平均成本选中第 440 次更新的模型。它在测试日的平均成本为 162.84，比手写规则低约 **6.5%**，比固定班表低约 **9.8%**；购电费、需量费和电池磨损费分别为 144.13、17.55、1.15。测试日不参与选模。训练种子从较大的整数范围随机抽取，代码没有排除验证或测试种子，因此其他运行配置理论上可能出现种子碰撞。这里的结果只适用于当前合成环境与代理费用，换训练种子、任务分布或预算仍需重新验证。

## 用于延伸实验

1. 把日终电量约束去掉，观察“只顾今天”的策略如何耗尽电池；解释为什么模拟器的边界条件会改变结论。
2. 将车辆离站时间随机化范围扩大，比较 PPO、固定班表和手写规则的成本及任务履约。
3. 只给策略不准确的天气预测，观察策略对预测误差是否稳健。
4. 改变 PPO 裁剪范围或移除动作掩码，讨论训练稳定性和约束违例。
5. 若要走向真实应用，先用真实历史数据校准热模型、电池效率、车辆行为和计费规则，再做离线回放、仿真压力测试与人工监管；本教学模型本身不应用于设备控制。
